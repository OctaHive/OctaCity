## 8. Verification commands

Each executable behavior above uses one public-boundary Red/Green cycle before moving to the next slice. Use the repository's existing fixtures and test contracts; a setup failure is not Red. Select the existing PostgreSQL/native qualification environment explicitly when those tests require it.

```sh
cargo test --locked -p octacity-server-application --lib issues
cargo test --locked -p octacity-server-application --lib ticket_delivery
cargo test --locked -p octacity-server-api-rest --test v1_handlers
cargo test --locked -p octacity-server --lib
cargo test --locked -p octacity-server-store-postgres
python3 tools/check_architecture.py
```

From `ui`, run the focused new/updated tests during each slice, then `pnpm api:generate`, `pnpm typecheck`, `pnpm lint`, `pnpm format`, `pnpm test:unit` and the affected Issue/Factory Playwright journeys. Regeneration must leave the generated schema and authorization inventory coherent. Reuse the existing packaged delivery qualification for final trusted publication; this checklist does not authorize effects against a production repository.
